Design harness · substrate decision

Where should the harness actually build?

The harness itself is settled. This is only about where the thing it produces lives: a React prototype we build ourselves, or Figma.

Written after building the React version far enough to judge it fairly. 30 Jul 2026.

What does not change

Step 0 and the gate · two isolated judges · adjudicate, the conflict rule, the pass budget · harvest and its routes · the day-1 assets. Four fifths of the harness is untouched either way.
One option asks us to build and maintain the place designs are made. The other uses the place designs are already being made.

What each one asks you to keep alive

React prototype (baby-PAI)

Things we build, then have to keep working

  • A React app: 149 files, dependencies, a build, a dev server
  • A third copy of the design system. Production React, then pai.css, then the app's wrappers, each hand-synced from the one above
  • Screens hand-ported from Figma, which drift from Figma and from the live product
  • An annotation tool written from scratch, because a prototype repo has no critique in it
  • A committed build or a deploy action, so a link exists
Five things to maintain

Figma

Things that exist and are maintained by someone else

  • No app, no build, no dev server. The artifact is a frame in a file already open
  • One design system: the published library, tied to the real codebase by Code Connect
  • The screens are the screens. Nothing to port, nothing to drift
  • Critique already happens there, and the edits designers make are the feedback
  • A Figma link is a link
Four things we get free

The point of the harness is that judgement piles up and the next run starts smarter. What stops a system like that is never the rate of learning. It is that upkeep eats the attention capture needed. In the React prototype, the rules and the substrate compete for the same hours. In Figma, the substrate is maintained by designers doing their normal job.

How each collects feedback

 React prototypeFigma

Coverage Patchy. Nothing annotated reads as approved You cannot forget to correct the agent
Strongest way to lock a rule in A lint check. The components are not the real ones A component in the real library

That last row does more than it looks. Once the only primary button in the library is navy, "navy is the action colour" stops being a rule anyone can break. No rule text achieves that.

What happens after a busy month

React prototype Dependencies age, ported screens drift, the three design-system copies diverge, annotation stops. The app still runs perfectly. It has quietly stopped representing the product, and now produces confident wrong judgements.
Figma Still current, because designers kept using it for real work.

One fails in the dangerous direction, misleading without looking broken. The other just gets out of date.

Who can use it

The React prototype's artifact is JSX, so changing it requires writing React, which most designers do not. A system built to capture designer judgement whose output most designers cannot edit has a problem tooling does not fix, and it runs only while one specific person is available. Figma's artifact is a frame.

Where the React prototype is genuinely better

FlowsA running app carries state between steps. Frames cannot, so what happens after the primary action can be drawn but not walked. The only irreplaceable loss.
ReachabilityThe harness proves an entry point exists by clicking through to it. You cannot click a frame.
Speed and controlA 700ms local build beats round trips, and something we own is easier to measure.
The React prototype's costs get worse every month. Figma's are the same size in a year as today. Three copies of the design system drift further every week. "A frame is not a flow" is exactly as true next year, and no worse.

Where I land

Figma. Not because it produces better designs, it does not. Beauty and brand alignment come from good anchors and a good judge, identical in both. Figma wins because the same harness costs far less to keep alive, collects feedback without anyone remembering to, fails safely when ignored, and can be run by every designer rather than one.

Confident about the maintenance argument: the three-copy problem, a 342k-line frontend with no isolated component dev, and a Figma lint that independently rediscovered two token gaps found by hand days earlier, are measured rather than argued.
Not confident about the practice: nothing has been generated in Figma yet, its speed is unmeasured, and the flow gap is untested against a real PRD.
Discount the fact that the React version was built first and then argued against. Weight the measured parts, not the recent ones.

What matters more than this choice

Neither option can tell whether its accumulated rules actually help. Without running the agent both with and without its guidance and comparing, both pile up confident nonsense at the same rate. And the one real harness run so far died at step 0, turning the PRD into a ratifiable checklist, which is identical in both.
