The design harness, building into Figma

A brief says what to solve; the assets on the left say how it should look and what real content goes in it. You ratify the requirements before anything is built. The artifact is a Figma frame rather than an HTML file, so the lint queries a node tree instead of reading markup — four of its six checks become structural facts rather than regex. Two judges then attack the result in parallel, one on the picture and one on the requirements, and your decisions write back into the assets so the next build starts smarter.

Drag any box — connections follow. Boxes marked substrate are the Figma layer, drawn explicitly so this can be compared like-for-like against the React prototype version. Changed and new mark what differs from the original harness; everything unmarked carries over as-is.

0FRAME THE BRIEF
preflight the assets — a missing one halts the run, it never degrades silently. Then turn the doc into a numbered requirements checklist, inheriting the template's defaults. Anything not decidable from a picture or the node tree is marked not checkable rather than fudged
writes → requirements.json
YOU RATIFY — surface · register · the checklist
a minute or two, honestly, before a frame is drawn — plus what came from the template and what is not checkable, because a checklist that cannot fail should be visible before you approve it
the only stop that waits for you · every other human moment ends the run instead
1aGROUND — pull what is live
read the route in pitchdeckdoclist before designing anything: the components that compose it, the copy inside them, the states it already has. Code Connect turns each into the Figma component to compose with. You are changing a screen, not inventing one — without this the harness redesigns the dashboard from scratch every run
writes → live.json, and the delta the brief is actually asking for
1bRETRIEVE
up to 3 anchors on exact surface + register. Anchors are Figma nodes, read through get_design_context, so the few-shot is the real frame rather than a description. Ground says what is there; anchors say how it should look
2GENERATE — use_figma
build against the ratified checklist, few-shot on the anchors, composing instances from the library rather than drawing shapes. Incremental: skeleton first, sections filled one call at a time, validated between. A number content.md cannot resolve halts the run, never invented
writes → the frame, and generated.json (the diff baseline)
3LINT — structural, on the node tree
every fill and stroke bound to a variable · every text node on the type scale · components are instances, not detached frames · containers use auto-layout · no placeholder copy · every number in content.md. Skips subtrees inside instances — the library's business, and not editable here
runs before any screenshot — a failure short-circuits, no judges, no pass spent
4SCREENSHOT THE STATES
get_screenshot per state frame, at every viewport. States are sibling frames, which is how designers already work, so there is no ?state= hack and no driven-state machinery. A state the checklist names but the file lacks is a blocking finding
5DESIGN JUDGE — does it look right?
fresh agent, an image model on the pictures — plus the rubric rows that load for this run and the exact anchors retrieve used. Never the brief, the checklist, the node tree, or the build reasoning
every finding located, and blocking or advisory · the anchor verdict is advisory — direction is yours
6PRODUCT JUDGE — does it solve the brief?
a second fresh agent — the brief, the ratified checklist, content.md, every state, and the node tree where it used to read code. Never the build reasoning, never the style rules. Per requirement: met / partly / missed. Anything the brief obliges that the checklist never listed halts the run
7DELIVER
the only way out, halts included — clean · budget spent · conflict · checklist bug · content gap · lint stuck. Always names what went unjudged and which checks were never written, so a thin pass never reads as a clean one
CORRECT — on a blocking finding
targeted use_figma edits against the named node ids, never a regenerate. Advisory findings never come here — they ride to Deliver as a list
one correction, then the whole frame re-verifies
ADJUDICATE — merge every verdict
lint · both judges. Delivers only on zero blocking findings. Calls a conflict when two blocking findings oppose each other on the same node. Owns the pass counter and writes the ledger
NODE DIFF — what you changed after
generation snapshots the tree it produced. Whatever the frame looks like later, the difference is what a human changed once the agent handed off — captured as a byproduct of working, so nobody has to remember to annotate anything
the highest-signal channel, and free
CORRECTIONS — from the conversation
"make the CTA navy, not orange" is a rule stated by the person with authority at the moment of judgement, and it is already a paired ❌/✅. Extracted from session transcripts, clustered by recurrence
said once, a note · said four times across three surfaces, a rule
YOU — the taste, and the call on the brief
Pick · Reject + why (the why is the payload) · Override a rule · settle a conflict or an obligation the brief implied but the checklist missed
HARVEST — pai-figma-build's closing phase
opens with one question, always: is this the reference for this surface and register? Then every other learning routes to exactly one home; you confirm each write, and every write prunes. Arrives with what the ledger already counted, not with a memory test
four rungs, weakest to strongest — prompt line · rule in the skill · lint check · a component in the library
the Figma file
no app, no build, no dev server. The artifact is a frame in a file designers already have open. States are sibling frames, variants are frames side by side — how the work already happens
generation composes instances into it
one design system
the published Figma library, maintained by designers as their actual job, bound to pitchdeckdoclist by Code Connect. No port, no re-sync, no third copy
prod components ↔ library, one binding
capture is a byproduct
the node diff, corrections in conversation, version survival, unpicked variants, the handoff diff. Nothing has to be built to manufacture judgement events, and nothing depends on remembering to annotate
every designer can edit it
the artifact is a Figma frame, so changing it needs no React. That matters for a system whose whole purpose is capturing designer judgement
a frame is not a flow
no state crosses frames. What you typed on step 1 is not there on step 2, so "what happens after the primary action" can be drawn but not walked
reachability is unverifiable
the design harness has the renderer drive a click path to prove an entry point exists. You cannot click a frame, so reach degrades to prototype links or to a judge's guess
every write is a round trip
use_figma runs incrementally with validation between calls. Slower per pass than a 700ms local build, and unmeasured across a full two-pass run
comments are not MCP-readable
Figma has the annotation layer we would otherwise build, and the tool surface cannot read it. The REST API can; that is a thing to build
variants — divergence
N frames side by side to pick a direction. All get the structural checks; the screenshots and the judges run only on the pick, which then takes the harness from step 0. Your choice of direction outranks the judges
requirements.json
the ratified checklist — surface · register · anchors · each requirement with its state and how it is reachable
generated.json
the node tree exactly as the agent left it. The baseline every later diff is measured against — without it, "what did the human change" is unanswerable
run.json · findings.jsonl
what happened — anchors, what was degraded, each pass's counts, the verdict, your rulings. Every finding appends to the ledger harvest counts from
CORPUS SWEEP — inside harvest
triggered, not remembered: the first build after the library changes, monthly otherwise. Walks everything older than the change
component → the library
a shape you keep rebuilding becomes a published component, proposed to the library owner. The strongest rung: once the only primary button is navy, "navy is the action colour" stops being a rule anyone can break
