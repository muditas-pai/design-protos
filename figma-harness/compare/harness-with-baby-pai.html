The design harness, building into a React prototype (baby-PAI)

A brief says what to solve; the assets on the left say how it should look and what real content goes in it. You ratify the requirements before anything is built. Two judges then attack the result in parallel — one on the picture, one on the requirements — a single step merges their verdicts, and your decisions write back into the assets so the next build starts smarter.

Drag any box — connections follow. Boxes marked substrate are the baby-PAI layer, drawn explicitly so this can be compared like-for-like against the Figma version.

SKILL: pai-build · you invoke it · every design build goes through it (stated in CLAUDE.md — prompt text, not enforcement)
run in parallel on the same draft · neither sees the other's findings
an investigation is a finding, not a brief. Someone turns it into a spec by hand first — the harness never invents requirements out of a conclusion

0FRAME THE BRIEF
preflight the assets — a missing one halts the run, it never degrades silently. Then turn the doc into a numbered requirements checklist, inheriting the template's defaults. Anything not decidable from a picture or the code is marked not checkable rather than fudged
writes → requirements.json
YOU RATIFY — surface · register · the checklist
a minute or two, honestly, before a line is generated — plus what came from the template and what is not checkable, because a checklist that cannot fail should be visible before you approve it
the only stop that waits for you · every other human moment ends the run instead · past rulings replayed here
1RETRIEVE
up to 3 anchors on exact surface + register, widening to surface, then register, if fewer than two hit. At least one human-made anchor whenever one exists; none at all is printed as an unanchored run
2GENERATE
build against the ratified checklist, few-shot on the anchors, starting from template.html — tokens only. A number content.md cannot resolve is emitted as {{content:key}} and halts the run, never invented
3LINT · two phases
source, before render: starts from template.html, no inline styles, no colour or spacing literals, no placeholder text. rendered, after step 4, once per state: numbers and prices against content.md, component markup, three a11y checks
a source failure short-circuits — no render, no judges, no pass spent
4RENDER THE STATES
Playwright, DPR 1, at 390 and 1440. Every state the checklist names. A state with a click path is driven through the UI — the renderer tried it, so the renderer decides reachability, and neither judge is asked to guess
5DESIGN JUDGE — does it look right?
fresh agent — the pictures, the rubric rows that load for this run, and the exact anchors retrieve used. Never the brief, the checklist, the code, or the build reasoning
every finding located, and blocking or advisory · the anchor verdict is advisory — direction is yours
6PRODUCT JUDGE — does it solve the brief?
a second fresh agent — the brief, the ratified checklist, content.md, every state, and the code. Never the build reasoning, never the style rules. Per requirement: met / partly / missed. Anything the brief obliges that the checklist never listed halts the run — the list was wrong, so correcting against it is pointless
7DELIVER
the only way out, halts included — clean · budget spent · conflict · checklist bug · content gap · lint stuck. Always names what went unjudged and which checks were never written, so a thin pass never reads as a clean one
CORRECT — on a blocking finding
targeted edits, never regenerate. Advisory findings never come here — they ride along to Deliver as a list
one correction, then the whole surface re-verifies
ADJUDICATE — merge every verdict
lint · renderer · both judges. Delivers only on zero blocking findings. Calls a conflict when two blocking findings oppose each other on the same element — a finding that merely survives a fix is not a conflict. Owns the pass counter and writes the ledger
ANNOTATE — designers, in the browser
click an element in any prototype, say what's wrong and what to do instead. The toolbar sends the selector, classes and computed styles with it, so a comment arrives already located. Element-level, and independent of approval — a file can carry open advisory comments and still be the best reference we have
said once, a note · said four times across three surfaces, a rule
YOU — the taste, and the call on the brief
Pick · Reject + why (the why is the payload) · Override a rule · settle a conflict or an obligation the brief implied but the checklist missed
HARVEST — pai-build's closing phase
opens with one question, always: is this the reference for this surface and register? — the only route that decides what the next build looks like. Then every other learning is routed to exactly one home; you confirm each write, and every write prunes — nothing here only grows. Arrives with what the finding log already counted, not with a memory test
two ladders — style: incident → rule → lint · product: miss → a checklist default. A new rule is born scoped to one surface. Surfaced nothing? It says so and stops
baby-pai-app
a React app we build and own — 149 files, deps, a Vite build, a dev server. Canonical screens, four altitudes (token · component · screen · flow) and a seam registry so an exploration can replace one part of a live screen
generation writes JSX into it
src/ds — the third copy
React wrappers over pai.css, which is itself a port of pitchdeckdoclist's uicomponents. Three copies of the design system, each of which must be re-synced by hand when the one above it moves
prod React → pai.css → src/ds
ported canonical screens
Dashboard and Editor hand-ported from Figma into JSX. They supersede key-screens/*.html and will drift from both it and Figma; keeping them current is a manual design job with an owner
annotation layer
built from scratch — Shift-C, hover to select, co-located *.annotations.json, a dev-server write endpoint. Manufactures the judgement events the loop needs, because a prototype repo has none lying around
coverage depends on remembering to annotate
RE-IMPLEMENT
the artifact is a prototype nobody ships. To become real it is rebuilt by eng in pitchdeckdoclist — a translation step the harness never sees, and where fidelity is lost
only React authors can edit it
a designer cannot open the artifact and change it. For a system whose purpose is capturing designer judgement, the artifact is in a language most designers do not write
dist/ + a deploy action
a shareable link needs a build committed, or a GitHub Action that publishes the whole repo. One shared build, so a syntax error fails it for everyone
crazy8s — divergence
8 variants to pick a direction. All get the source checks; the rendered checks and the judges run only on the pick, which then takes the harness from step 0. Your choice of direction outranks the judges
requirements.json
the ratified checklist — surface · register · anchors · each requirement with its state and how to reach it
run.json · findings.jsonl
what happened — anchors, what was degraded, each pass's counts, the verdict, and your rulings. Every finding is appended to the ledger harvest counts from
CORPUS SWEEP — inside harvest
triggered, not remembered: the first build after design-system/ changes, monthly otherwise. Walks everything older than the change; only the token re-sync leaves as a PR
component PR
a snippet you keep rebuilding → proposed to the design-system owner, never ported directly
